# Objetivo

1. Corregir el filtro "Exportar Internacional" (https://www.decawebservice-01.com/telcel/phones-filtered.php?export=intl) ahora tiene que filtrar la lineas internacionales con las siguientes opciones que son condiciones OR:
  1.1. lineas que empiecen con '+', empiece con '1' y en total sean 11 digitos. Ej. +14243090604.
  1.2. Lineas que empiecen con '1', no empiecen con '+' y en total tenga 11 digitos. Ej. 16615209812
  1.3. Para filtrar se toma la opcion 1.1, 1.2 con un OR. Ej. se debe verificar la opcion 1.1 luego la opcion 1.2, al final deben salir como en el resultado lineas internacionales como: +14243090604, +15303589169, 16615209812, 16615200392, +13239701924.

2. Corregir los rangos de tiempo para que no exista ningun hueco ni duplicado entre periodos.
  2.1. El arreglo "$minutos" debe quedar:
```
$minutos = array(
	10  => 60,
	60  => 120,
	120 => 180,
	180 => 240,
	240 => 300,
	300 => 360,
	360 => 1440
);
```
  2.2. En todas las consultas SQL que filtran por "$from" y "$to", el limite inicial debe ser inclusivo y el limite final exclusivo:
```sql
reportDate <= ADDDATE(UTC_TIMESTAMP(), INTERVAL -$from MINUTE)
AND reportDate > ADDDATE(UTC_TIMESTAMP(), INTERVAL -$to MINUTE)
```
Esto representa rangos de antigüedad [from, to), por ejemplo:
- 10 <= minutos < 60
- 60 <= minutos < 120
- 120 <= minutos < 180
- 180 <= minutos < 240
- 240 <= minutos < 300
- 300 <= minutos < 360
- 360 <= minutos < 1440

De esta forma una linea con exactamente 60 minutos pertenece solamente al segundo rango, una de exactamente 120 minutos solamente al tercero, etc.

  2.3. Las etiquetas de horas deben calcularse con "$from/60" y "$to/60". No se debe restar 1 a "$from", ya que con los nuevos limites produciria valores incorrectos como 0.98 hr para 60 minutos.

3. Fijar una sola hora UTC al inicio de cada ejecución para que todos los rangos de tiempo usen exactamente la misma referencia temporal.
  3.1. Definir una sola vez:
```php
$now_utc = gmdate('Y-m-d H:i:s');
```
  3.2. Todas las consultas que filtran por "$from" y "$to" deben usar "$now_utc" en lugar de ejecutar "UTC_TIMESTAMP()" de forma independiente:
```sql
reportDate <= ADDDATE('$now_utc', INTERVAL -$from MINUTE)
AND reportDate > ADDDATE('$now_utc', INTERVAL -$to MINUTE)
```
De esta forma un registro no puede cambiar de periodo durante la misma ejecución por los segundos transcurridos entre una consulta y otra.

4. Mantener las etiquetas de horas calculadas con "$from/60" y "$to/60", redondeadas a dos decimales. Por ejemplo, 10 minutos equivalen a 0.1667 horas y deben mostrarse como "0.17 hr". No volver a usar "($from-1)/60".
